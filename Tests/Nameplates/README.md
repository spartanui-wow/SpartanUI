# Nameplate tests

Headless checks for `Modules/Nameplates` (plan: `openspec/nameplates-revamp.md`, section 8, 6.3, Decision 6).
Nothing here ships: `.pkgmeta` ignores `Tests`.

```
python Tests/Nameplates/run.py                     # stylua, lint, every suite on every default flavor
python Tests/Nameplates/run.py --flavor forever    # one flavor (repeatable)
python Tests/Nameplates/run.py --suite inert       # suites whose file name contains "inert"
python Tests/Nameplates/run.py --only "restricted" # tests whose full name contains the text
python Tests/Nameplates/run.py -v                  # full failure output and skipped tests
```

`run.py` exits with 1 when anything fails. Other switches: `--runtime lua51|luals`, `--jobs N`,
`--syntax-only` (formatting differences warn instead of failing), `--skip-stylua`, `--skip-lint`.

Needs: Python 3 with `lupa` (`pip install lupa`), `stylua` on PATH, and the LuaLS binary from the
sumneko VS Code extension (found automatically; set `NP_LUALS` to override). Regenerating the API
data needs `C:/code/WOWUICode/wow-ui-source` (set `WOW_UI_SOURCE` to override).

## Runtimes

Every run is its own process, so globals never leak between suites or flavors.

- **lua51** (lupa): real Lua 5.1, like the game. Use it for anything value-sensitive (Store, CVars,
  Share, Migrate) and for suites that load the module.
- **luals** (the LuaLS binary): Lua 5.4/5.5 with 5.1 shims. `tostring(150.0)` still gives `150.0` when
  a float is concatenated, and Lua 5.5 refuses to compile assignments to `for` loop variables, which
  is valid Lua 5.1. When that happens `run.py` reruns the suite under lua51 and prints a note.

A suite picks its runtime on its first line: `-- @runtime lua51`, `-- @runtime luals` (the default)
or `-- @runtime both`.

## Writing a suite

A suite file is called with `(M, H, T)`: the mock, the loader and the test API.

```lua
-- @runtime lua51
local M, H = ...

describe('health part', function()
	before_each(function()
		M.ResetRecords()
	end)
	it('fills the bar under secrets', function()
		local token, base, unit = M.ShowPlate({ name = 'Gnoll', health = 300, healthMax = 600 })
		M.SetRestricted(true)
		-- ... drive the engine ...
		assert.secret(UnitHealth(token))
		M.SetRestricted(false)
	end)
end)
```

- `describe(name, fn)`, `it(name, fn)`, `before_each(fn)`, `after_each(fn)`, `pending(name, reason)`,
  and `skip(reason)` inside a test.
- `assert.equal`, `not_equal`, `same` (deep), `truthy`, `falsy`, `is_true`, `is_false`, `is_nil`,
  `not_nil`, `matches(str, pattern)`, `near(a, b, eps)`, `errors(fn, plainText)` (returns the
  message), `no_errors`, `secret`, `not_secret`, `contains`, `not_contains`,
  `empty(t, msg, describeItem)`, `fail(msg)`, `reported(plainText)`.
- `assert.equal` refuses secret values; reveal them first with `M.S.Reveal(v)`.
- A test fails when code run by the mock reports an error through the error handler (script handlers,
  timers, event handlers). Take an expected one with `assert.reported('text')`.
- Globals: `HARNESS_ROOT`, `FLAVOR`, `RUNTIME`.

## The mock (`M`)

**Strict by data.** A global function, namespace function, widget method, event or `Enum` value exists
only when the flavor's data file lists it. Anything else is nil, so calling it errors. Documented
things the mock has no behavior for are stubs that return nothing; each call is counted in
`M.rec.unmodeled["Type:Method"]` or `["C_Name.Function"]`, and `M.FnCalls(label)` returns the arguments.
Unknown frame types and templates, unknown events, invalid anchor points and lowercase font flags error.

**Secrets.** `M.S.Wrap(v)` makes a secret, `M.S.Reveal(v)` reads it (tests only), `M.S.IsSecret(v)`.
A secret errors on arithmetic, comparison, length, indexing, assignment and calls; concatenation,
`tostring` and `string.format` give secret strings; `type()` reports the hidden type. On clients with
secrets, functions and methods documented `SecretArguments = AllowedWhenUntainted` or `NotAllowed`
raise when handed a secret; `AllowedWhenTainted` ones take it. `Duration` and `DurationTextBinding`
objects are exempt (`M.secretArgExempt`; patterns.md 2026-06-17 says their setters take secrets in
game). No runtime mock can catch boolean tests, comparison against another type or secret table keys:
the lint does.

**Restricted mode.** `M.SetRestricted(true [, categories [, force]])` makes unit functions return
secrets for any unit but the player, following each function's documented markers (`SecretReturns`,
`SecretWhenUnitIdentityRestricted`, `RequiresUnitIdentityAccess`, ...). Categories: values, identity,
comparison, casting, auras, threat, stats, possession, combat (pvp only when asked). It applies only on
flavors with secrets unless `force` is true, which borrows Retail's markers. `C_Secrets` answers follow
it, and `C_NamePlate.GetNamePlateForUnit` errors for restricted tokens that are not nameplate tokens.
A unit spawned with `restricted = false` stays readable.

**World.** `M.AddUnit(spec)`, `M.ShowPlate(unitOrSpec)` (fires `NAME_PLATE_CREATED` for a new base,
then `NAME_PLATE_UNIT_ADDED`; returns token, base, unit), `M.HidePlate(token)`, `M.SetTarget`,
`M.SetFocus`, `M.SetMouseover`, `M.UpdateUnit(unit, fields, events)`, `M.StartCast(unit, cast)`,
`M.StopCast(unit, how)`, `M.SetThreat(mob, holder, entry)`, `M.ApplyAura(unit, aura)`,
`M.RemoveAura(unit, id)`, `M.SetPlace(place)`, `M.player`. Unit spec fields: name, level, health,
healthMax, power, powerMax, powerType, reaction, canAttack, canAssist, isPlayer, playerControlled,
classification, isBoss, isLieutenant, tapDenied, questBoss, inCombat, raidMarker, class, className,
creatureType, npcID, widgetsOnly, isGameObject, forbidden, restricted, absorbs, role. Base plates carry
Blizzard's `UnitFrame` (with `healthBar`, `castBar`, `name`, `WidgetContainer`, `SoftTargetFrame`).
Hit-test points can change only while `NAME_PLATE_UNIT_ADDED` is being delivered.

**Time, events, combat.** `M.Fire(event, ...)` (unknown events error; unit filters from
`RegisterUnitEvent` apply), `M.FireIfKnown`, `M.Advance(seconds)` (timers plus one OnUpdate pass every
50 ms), `M.Login(addonName)`, `M.EnterCombat()` (`PLAYER_REGEN_DISABLED` fires before lockdown starts),
`M.LeaveCombat()`. Functions documented `HasRestrictions` are blocked in combat and recorded.

**CVars.** The store holds every CVar the branch's own code names. `M.SetCVarState(name, { value,
default, secure, account, character, locked, readOnly })` adds or changes one, `M.RemoveCVar(name)`
removes it. Secure CVars written in combat return nothing and are recorded in `M.rec.blocked`.
Defaults are `'0'` unless a suite sets them; bitfields keep bit `index - 1` (unverified in game).

**Records.** `M.rec.events`, `hooks`, `cvarWrites`, `globals` (named frames, textures, fonts), `tickers`,
`onUpdates`, `blocked`, `unmodeled`; each entry has `where` (file:line of the addon code). Also
`M.ResetRecords()`, `M.SnapshotGlobals()`, `M.NewGlobals(snapshot)`, `M.ActiveOnUpdates()`,
`M.ActiveTickers()`, `M.RegisteredEvents(frame)`, `M.Calls(obj, method)`, `M.Get(obj, key)` (widget
state such as `alpha`, `text`, `value`, `barColor`), `M.HasMethod(type, method)`.

**Extending.** Behaviors live in tables keyed by name: `FN.Name` (global functions), `NS.C_X.Name`
(namespaces), `W.Method` (widget methods), `WT.Type.Method` (one type only), and `framexml.lua` for
FrameXML globals and templates. After adding an `FN.` or `framexml.lua` entry, run
`python Tests/Nameplates/api_matrix.py --generate` so the data files record where it exists.

## The loader (`H`)

- `H.LoadLibs()`: real Ace3 from `libs/Ace3` (AceGUI core included) and LibSharedMedia; AceConfigDialog is
  a recording stand-in (`H.dialogCalls`).
- `H.LoadCore(opts)`: reads `Modules/Nameplates/Load.xml` at run time and loads each file in order with
  `(addonName, ns)`; includes are followed, virtual XML templates are registered. The default addon
  name is `NameplatesTestHost`, so a core that leans on its carrier's name shows up.
  Options: `xml`, `addonName`, `ns`, `libs = false`, `libat = false`.
- `H.HostStub(overrides)`: a host table in the shape of plan 6.11 with neutral names; calls are recorded
  in `H.hostCalls`, logger lines in `H.logs`.
- `H.LoadSpartanUIHost(opts)`: loads `Host/SpartanUI.lua` against the SUI mock (a real AceAddon with
  L, logger, DBM, Options, OptionsWindow.Stage, Setup, ThemeRegistry, Lib.LSM, DB, SpartanUIDB and the
  module helpers). The old `Nameplates` module is created first, as in Phases 2 to 4a
  (`oldModule = false` skips it). `H.suiMissing` lists SUI fields the host read that the mock lacks.
- `H.InstallLibATStub()`: a permissive LibAT stand-in that records calls (`H.libatCalls`).
- `H.FreshCore(opts)`: a new, separate copy of the core with its own SavedVariable
  (`NameplatesTestDB<n>`), so one suite can start from several database states. Options: `saved` (raw
  SavedVariable table to start from), `host` (HostStub overrides), `before(P)` (runs before
  `P:Initialize`, for adding patches or changing `Config.SCHEMA`), `initialize = false`.
  Returns `P, ns, savedVariableName`.
- `H.LoadNameplatesLikeTheGame(opts)`: loads the real old `Modules/Nameplates.lua`, every core file and
  the host in `Modules/LoadAll.xml` order with addon name `SpartanUI`, against the SUI mock without a
  pre-made module. `SUI.UF` and `SUIUF` are `H.DeepProxy` stand-ins (calls in `H.oldCalls`). Option:
  `saved` (raw `SpartanUINameplatesDB`, for example the tester switch). Returns `SUI, ns, module`.
- `H.NameplateLoadEntries()`: the nameplate slice of `Modules/LoadAll.xml` (old module to host), its
  first and last index, and every entry.
- `H.CharacterKey()`: the AceDB character key of the mock's player, for seeding `char` data.
- `H.DeepProxy(path, calls)`: a stand-in where every index and call returns another stand-in.

Loading SpartanUI's whole TOC is not done: on Era about 140 of 482 files fail in the strict client
(missing FrameXML such as `RegisterStateDriver`, `Minimap` and Blizzard XML templates, and
Libs-AddonTools), none of them nameplate files. `loadorder_spec` checks the TOC and `LoadAll.xml`
statically instead and loads the nameplate slice for real.

## The lint

`python Tests/Nameplates/lint.py` (or `--self-test`). Rules are data in `lint_rules.json`:

- host names: no `SUI`, `SpartanUI` (any case), `Interface\AddOns\...` paths or host globals under
  `Modules/Nameplates` outside `Host/`, in code, strings and comments;
- no `print(` anywhere in the module;
- Lua 5.1 only: no `goto`, `continue`, `::`, `//`, `&`, `|`, `~`, `<<`, `>>`;
- only `Engine/Source.lua` may call `Unit*` globals, `C_UnitAuras` or
  `C_NamePlate.GetNamePlateForUnit` (calls, aliases and `pcall(fn, ...)` count; presence tests do not);
- the `*Secret` convention (a heuristic over tokens): a value from a call to a function or method named
  `...Secret`, or a variable or field named `...Secret`, fails when `==`, `~=`, `<`, `>`, `<=`, `>=`,
  `and`, `or`, `not`, `if`, `elseif`, `while`, `until`, arithmetic, `#` or `[` sit directly before it,
  or a comparison, arithmetic, `[`, `.` or `:` sits directly after it; when it is stored in a name that
  does not end in `Secret` or in a table; or when it is passed to a function that is not a sink. Sinks
  are `Secret.SINKS` in `Core/Secret.lua` (the authority), the rule's list, every game API documented
  `AllowedWhenTainted` in any data file, every function `Core/Secret.lua` defines, and any function
  whose name ends in `Secret`, minus the rule's `notSinks` (`SetAlpha`, documented but kept off until
  an in-game check). `type(xSecret) == 'nil'`,
  `return`, concatenation and `C_Secrets.Should...BeSecret()` pass. PascalCase names that are not called
  (`kind.TestSecret`) are function references and pass. `Core/Secret.lua` itself is exempt;
- no tables keyed by `auraInstanceID`; no literal global names in `CreateFrame` and friends or in XML.

Suppress one finding with `-- np-lint: allow <rule-id> <reason>` on the line or the line above. Host,
print, Lua 5.1 and source-only rules cannot be suppressed.

## API data and the matrix

`python Tests/Nameplates/api_matrix.py` prints every API `Modules/Nameplates` calls against Retail, PTR,
Forever, Mists, Titan, TBC and Era, with the lines that use anything missing somewhere.
`--generate` rebuilds `data/*.lua` (about a minute and a half). Each file holds the documented
functions, namespaces and widget methods (with their secret markers), events, enums and constants;
engine functions the docs leave out but Blizzard's code calls (only for names the mock models or the
module calls, so regenerate when the module starts using a new one); FrameXML names and templates the
mock models; aura container methods; and the CVars the branch's code names. Enums Blizzard's code uses
but the docs omit get placeholder values (1..n).

## Unverified in the mock

Titan's project id; whether `UnitHealthPercent` returns 0-1 or 0-100 (the mock uses 0-1); the CVar
bitfield encoding; CVar defaults; the `AllowedWhenUntainted` reading (raise on secrets) and the
Duration exemption; `RAID_CLASS_COLORS` values (stand-ins). Each one is a place an in-game spike may
correct the mock.
